# 报告数据契约


> 当前交付约束见[输出规则](report-output-v4.md)，报告规则 `{{REPORT_RULE_VERSION}}`，AI 契约 `{{AI_CONTRACT_VERSION}}`。数据范围见[字段说明](fields.md)。

## 报告数据范围

DOCX 与 PDF 应包含一致的企业、期间、分析文字、风险事项、表格和图表。风险等级、客观事实、数据不足及不适用须分别表达；缺少资料不能写成未见异常。

报告中的金额、比例、期间、主体和风险事项应来自已准备工作区。Agent 解释已有事实及其限制，不补充来源未提供的事实。

按所读取的对象区分字段含义：接口原始响应见[API 契约](api.md)、[模块字段](fields.md)及[结构化数据](structured-data.md)；正文写作以 `report-read/report-refs` 提供的事实和展示值为准。相同的 `status`、`value` 或 `code` 在不同对象中不一定具有相同含义。

`report-model.json` 中与分析有关的字段：

| 路径 | 含义及使用方式 |
| --- | --- |
| `companyName/uscc`、`startTime/endTime` | 当前企业及报告范围，不是单条申报或事件的日期。 |
| `generatedAt/taskId/ruleVersion` | 报告准备时间、任务标识和规则版本。 |
| `sections[].semanticId` | 稳定章节标识；提交正文时作为 `sectionId`，不使用显示编号替代。 |
| `sections[].sourceSectionId/displayNumber/title/level` | 章节来源编号、当前显示编号、标题和层级；客户文档引用章节时用标题。 |
| `sections[].narrative.mode/minItems/maxItems` | 本节写作类型及条目范围，按实际返回值填写，类型含义见[输出规则](report-output-v4.md)。 |
| `sections[].findingIds/dataNotice/blocks` | 本节已确认风险ID、数据限制及已准备的正文、表格或图表内容。 |
| `findings[]` | 已确认风险事项；`id/riskThemeId/title/level` 是事项标识、风险主题标识、标题和等级。`level` 为“高风险/中风险/低风险”，不得自行重判。 |
| `findings[].moduleCode/period/periods/evidence/recommendation` | 来源模块、期间、期间集合、证据及对应动作；`periods` 可缺省。 |
| `findings[].confidence/verificationRequired/amount/signalTypes` | 证据置信说明、是否仍需核实、事项金额及信号类型；金额须结合事项证据理解，不等同于确定应补税额。 |
| `evaluations[].ruleId/outcome/evidence/finding` | 单条规则的标识、评价结果、证据及可选风险事项；`outcome` 为 `risk`（确认风险）、`clear`（该规则未见异常）、`not_applicable`（不适用）、`data_insufficient`（资料不足）。资料不足不是低风险或无风险。 |
| `warnings/omittedReasons` | 已知限制及未显示章节的原因；省略原因 `no_risk/not_applicable/data_insufficient/dependency_deferred` 分别为无对应风险、不适用、资料不足、依赖条件暂未满足，不能据章节未显示推定正常。 |
| `taxFields/calculations/filingEvents` | 单元格事实、计算结果及申报事件；字段见下文，仅在需要追溯时读取。 |

## TaxPeriod

`report-model.json` 的税表事实、申报事件和有关记录使用以下期间对象：

| 字段 | 类型 | 含义及使用方式 |
| --- | --- | --- |
| `start/end` | 日期字符串 | 实际所属期起止日期，首尾均包含，不以申报或缴款日期替换。 |
| `bucketMonth` | 字符串 | `end` 所在的 `YYYY-MM` 月份，用于归集；季报进入末月不表示每月申报。 |
| `cycle` | 字符串 | `月报/季报/年报/按日/不定期`，以记录实际期间判断，不按查询跨度猜测。 |
| `display` | 字符串 | 可读的完整所属期说明。 |
| `declarationDate/paymentDate` | 日期字符串，可缺省 | 实际申报日期及缴款日期，与所属期分别保留。 |
| `basis` | 字符串 | `税款所属期` 或 `缴款日期`；后者表示缺少所属期时采用缴款日期归集，不能声称已经取得实际税款所属期。 |

实际申报记录区分所属期开始及结束、月报/季报/年报/按日/不定期周期、申报日期和缴款日期。各税种 `effectiveRecords` 是当前分析版本，申报记录使用 `declaredRecords`；`recordHistory` 用于追溯更正和作废历史，`undeclaredRecords/todoRecords` 不进入已申报统计，税费种认定只作补充。

查询记录可能包括次年报送的汇算及后续更正，应按实际所属期区分当前分析记录和前期参考。需要累计或差分时，年初至报告开始前的记录仅作参考，不混入当前期间合计。查询覆盖存在缺段时，应明确说明，不能声称期间完整。

财报先依据报表准则识别金额口径，再依据所属期起止确定月度、季度或年度。企业会计准则的利润表和现金流量表流量字段按年内累计处理：首期直接取累计，后期减同年同周期相邻上期累计，还原当月/季；不得使用“上期金额”（上年同期）列。小企业会计准则及其他准则默认按所属期直接取本期金额，明确的本年累计列仍单独保留累计含义。原累计和还原金额分开保存；缺相邻前期不补零、不以年报替代。资产负债表的资产、负债等时点余额不做差分。年中开始报告所需参考财报保存在 income_statements.yearToDateReference.records，不混入报告期。次年报送的上年第四季度或12月仍归上年。完整日期以及带时分秒的日期保留实际日；仅来源明确为月份时才补月初/月末，申报和缴款日期不代替已有所属期。

纳税人资格只从税局证据解析。优先使用 `taxpayerInfo.taxpayerQualiInfo`、`identifyInfo` 的明确资格字段，`nsrzg/Nsrzg` 使用 `0=一般纳税人、1=小规模纳税人`，`NsrzglxDm=201` 识别为增值税一般纳税人。档案缺少资格时，税局用途确认接口明确返回“不适用一般纳税人功能”可作为小规模纳税人证据。绑定企业列表中的 `nsrzg` 可能滞后，不得参与报告判定。

申报及财报的使用方式见[结构化数据说明](structured-data.md)。按实际主附表及中文行列区分一般项目/即征即退项目、货物劳务/服务业务、本期/累计/上年、资产/负债侧及期初/期末。没有明确列归属的多值行保持缺失，不能按首列或末列猜取，空单元格不补零。

4.2金额单元格及各级合计只读取缴款事实，不使用申报额代填；展示元、两位小数的纯数字。明确实缴为零显示0.00，未取得实缴记录显示“—”。完整月份轴从任务 `startTime` 到 `endTime` 逐月生成。季度和不定期记录按所属期结束月份进入月度矩阵；年度汇算单独列示，不与预缴重复累计。完整起止日期保留在证据资产中。不存在的月份和无法确认的金额保持缺失并显示“—”，不得补零。缴款优先使用税款所属期；只有缴款日期时，`basis` 明确记录为缴款日期口径。

4.6按实际增值税月报/季报周期展示税负率。累计收入扣减紧邻前期同年累计数；季度利润表优先，未申报同期利润表才采用指定增值税栏次。比较时核对同期收入、全部税费、企业承担税费和各自税负率，前3期比较须区分百分点差与相对百分比偏离。脚本计算使用未舍入值，AI 正文使用已提供的 `display`，结合单位、期间、基期及来源说明解释，不自行重算；未知值保持缺失，不把缺数画成零。

## AI 工作区契约

AI 契约版本固定为 `{{AI_CONTRACT_VERSION}}`。`report-prepare` 输出以下互相校验的文件：

- `manifest.json`：任务和输入摘要、`{{REPORT_RULE_VERSION}}` 规则版本、章节和风险 ID 集合。
- `source-snapshot.json`：17 模块结构化快照及公共税表。
- `report-model.json`：报告的事实、章节、风险、表格及图表数据。
- `analysis-data.json`：冻结指标底稿；`analysis-sections/<semanticId>.json`为完整分节阅读卡，按display提供值和期间/基期、核验范围及限制；未舍入输入仅在完整底稿。日常分析通过report-read获取analysis-batches中的体积受控阅读包，完整对象可用report-refs查询。
- `analysis-task.md`：本次分析清单和允许使用的引用。
- `analysis-output.json`：保存通过 `report-write` 合并的 Agent 正文及对应任务信息。

DOCX 与 PDF 的正文和数据应一致；两种成品均须检查。不要向客户文档加入 API Key、登录信息或原始接口响应。

analysis-output.json保留版本、任务及输入摘要；sectionOrder完整且唯一。conclusion.items为3—5条重点，首条总体风险，优先风险与动作在同一点对应，保留最重要数据限制。sections按照narrative.minItems/maxItems填写，DESCRIPTION允许空items；脚本固定缺数、不适用和未见异常文字。动态事实、期间和趋势均须绑定可信引用，最终展开内容同样接受校验。

正文或引用修改后，须重新执行 `report-validate`，通过后再渲染。同一工作区可以修改并重新校验，不要手工修改来源或摘要来跳过检查。

## AI 读写字段

以下为本地报告命令的 JSON 字段，直接位于命令结果中，不套用远程接口的 `code/message/data` 层。完整操作顺序见[报告工作流](report.md)。

### 读取结果与进度

`report-read`：

| 字段 | 类型 | 含义及使用方式 |
| --- | --- | --- |
| `status` | 字符串 | 命令成功返回 `success`，不表示全部数据无缺失或报告已写完。 |
| `analysisDataDigest` | 字符串 | 当前分析底稿摘要，本批及结论提交时都原样复制，不自行生成或修改。 |
| `content` | 字符串 | 本批或指定章节的 Markdown 阅读材料，包含目标、事实、范围、限制和可用引用；不是待提交的正文 JSON。 |
| `batchId` | 字符串，可缺省 | 本次返回的批次标识；按节读取及综合结论材料可不提供。 |
| `progress` | 对象 | 当前写作进度，字段见下表。 |
| `elapsedMilliseconds` | 整数 | 本次本地命令耗时，单位毫秒，不包含 AI 写作耗时。 |

`progress` 同时出现在 `report-read` 与 `report-write` 返回中：

| 字段 | 类型 | 含义及使用方式 |
| --- | --- | --- |
| `completedSectionIds` | 字符串数组 | 已满足当前结构及引用要求的待分析章节；不是对自然语言质量的确认。 |
| `pendingSectionIds` | 字符串数组 | 仍待填写或修正的章节标识。 |
| `conclusionPending` | 布尔值 | `true` 表示综合结论仍待填写或修正。 |
| `nextBatchId` | 字符串，可缺省 | 下一个含待完成章节的批次；没有待完成章节时缺省，`--next` 将返回综合结论材料。 |

返回中没有 `complete` 字段。只有 `pendingSectionIds` 为空且 `conclusionPending=false` 才表示当前写作进度完成；之后仍须执行整份 `report-validate`。

### 查询引用

`report-refs` 返回 `status`、`analysisDataDigest`、`total`、可选 `nextOffset` 和 `matches`。`total` 为符合筛选条件的全部匹配数，不是本页条数或业务记录总数；`nextOffset` 是下一页起点，缺省表示无下一页。`matches[]` 字段如下：

| 字段 | 类型 | 含义及使用方式 |
| --- | --- | --- |
| `id` | 字符串 | 可引用对象的准确ID；有效时原样写入 `evidenceRefs`，不要拼接或猜测。 |
| `sectionId` | 字符串 | 所属章节标识；部分通用事实可无具体章节值。 |
| `name` | 字符串 | 指标或事实的中文名称；同名项仍可能有不同主体、期间或口径。 |
| `display` | 字符串，可缺省 | 已确定口径的展示值，含数值或文字；`status` 不是 `present` 时不返回此字段。 |
| `unit` | 字符串，可缺省 | 金额、百分数、百分点、次数等单位；不能仅凭数值大小推定单位。 |
| `period/basePeriod` | 字符串，可缺省 | 当前期间与比较基期；两者不得对调。 |
| `scope` | 字符串数组，可缺省 | 此指标覆盖的期间或对象集合；子集极值不能扩展到未覆盖的全部期间。 |
| `subject` | 字符串，可缺省 | 主体筛选与定位信息；结合名称、口径和阅读材料确认实际对象。 |
| `algorithm` | 字符串，可缺省 | 计算或取值口径，帮助解释分子、分母、方向和范围，不要求 AI 重算。 |
| `status` | 字符串 | 对应事实的可用状态；只有 `present` 可作有效引用。其他状态保留其限制，不能因命令成功而视作有效。 |

多个筛选条件同时满足才返回。名称按包含匹配；主体条件在主体信息、展示内容及覆盖集合中查找包含项，不等于已完成主体身份核验。章节、ID、期间及基期按精确匹配；不确定期间格式时先查名称，再复制返回的完整期间。缺失 `unit/period` 不能自行补出货币、年份或月份。

### 指标与章节材料

`analysis-data.json` 顶层 `ruleVersion` 为规则版本，`sections` 为完整分节底稿，`actions` 为可选的已确认风险对应动作。日常写作用 `report-read`，补查用 `report-refs`，不需要每批重读整份文件。分节对象字段如下：

| 字段 | 类型 | 含义及使用方式 |
| --- | --- | --- |
| `sectionId/title` | 字符串 | 章节标识及中文标题。 |
| `objective.goal` | 字符串 | 本节分析目标，不是企业事实。 |
| `objective.sourceSectionId/wordBlock` | 字符串/整数 | 目标定位信息，不作为业务证据或正文内容。 |
| `mode` | 字符串 | 本节写作类型；按返回的条目要求及[输出规则](report-output-v4.md)处理。 |
| `sampleOnly` | 布尔值，可缺省 | `true` 表示当前资料覆盖不完整，只能描述已取得样本；这些样本仍是本企业已取得的事实，不是演示数据。结论不得扩展到全部业务，须保留覆盖限制。 |
| `metrics` | 数组 | 本节指标，字段见下表。 |
| `focus[]` | 对象数组 | `id` 为重点标识，`goal` 为分析目标，`required` 为重点要求标记，`evidenceRefs` 为有关引用ID；引用须结合实际事实选用，不是全部抄写清单。 |
| `constraints` | 字符串数组 | 数据缺失、范围或可比性限制，应约束结论。 |
| `guidance` | 字符串，可缺省 | 本节分析方向，不是事实，也不增加通用必填项。 |
| `relatedSections/findingIds` | 字符串数组，可缺省 | 关联章节及已确认风险标识，不据关联关系新增风险。 |
| `references[]` | 对象数组，可缺省 | `id/kind/label/value/sectionId` 分别为引用ID、类型、中文标签、展示内容及可选所属章节；此处 `value` 是字符串，不能按数值指标解析。 |
| `coverage[]` | 对象数组，可缺省 | 主体身份及查询覆盖，见下文。 |

完整底稿 `metrics[]`：

| 字段 | 类型 | 含义及使用方式 |
| --- | --- | --- |
| `id/name/kind` | 字符串 | 指标引用ID、中文名称及类别。 |
| `value` | 数值 | 计算结果；只在 `status=present` 时有有效数值含义，默认0不能证明真实为零。文字指标以 `display` 为准。 |
| `display` | 字符串 | 正文采用的展示值，连同 `unit/period/basePeriod/scope` 理解，不由舍入展示值倒推原值。 |
| `unit` | 字符串，可缺省 | 指标单位。单位为 `%` 的指标数值已按百分数口径提供，不再次乘100；百分点与相对百分比变化分开。 |
| `period/basePeriod/scope` | 字符串/字符串/字符串数组，可缺省 | 当前期间、比较基期和实际覆盖集合；不能混用月、季、年或以参考期代本期。 |
| `algorithm` | 字符串 | 取值或计算口径，说明差额方向、分母和适用范围。 |
| `inputs` | 对象数组，可缺省 | 计算输入，见下文 `calculations[].inputs[]`；阅读材料可能不附全部输入，不等于来源缺失。 |
| `sourceRefs` | 字符串数组 | 原始来源定位信息，不自动等于可提交的引用ID；`evidenceRefs` 使用阅读材料或引用查询返回的有效 `id`。 |
| `status` | 字符串 | `present` 为有效指标，`missing` 为缺失，`conflicting` 为数据冲突，`unavailable` 为当前条件下不可计算或不可用；只有 `present` 可作有效引用，其余不得当成零或正常。 |

比例须按所在层级解释：原始主体 `transactionShare=0.2` 表示20%，而写作指标 `unit="%"`、`value=20`、`display="20.00"` 已是20%，结合单位写成20.00%，不能再次乘100。客户、供应商的报告占比使用已准备的同方向发票净额计算结果，不能直接拿原始 `transactionShare` 替换。罚款原始字段明确为万元时换算为元；准备后的展示值若已为元，不重复乘10000。只从字段定义、单位及算法确定口径，不用“值小于1”等猜测规则。

`analysis-sections/<sectionId>.json` 是分节阅读卡，结构与完整底稿不同：它保留 `sectionId/title/objective/mode/sampleOnly/focus/coverage/constraints/guidance/relatedSections/findingIds/references`，指标与限制分别放在以下位置：

| 阅读卡字段 | 含义及使用方式 |
| --- | --- |
| `metricGroups[].id` | 比较或业务对象的分组标识，不代替具体指标引用。 |
| `metricGroups[].metrics[]` | 只提供有效指标的 `id/name/display/unit/period/basePeriod/scope/algorithm`；不提供原始 `value/inputs`。正文使用具体指标 `id` 和 `display`。 |
| `limitations[]` | 不可用指标的 `id/name/period/basePeriod/scope/status/reason`，分别说明对象、期间、状态和限制原因；不提供可引用数值，不得恢复成0。 |

阅读卡中 `coverage` 的口径与下表一致；`report-read.content` 将这些信息组织成 Markdown，不能按 `content.metrics` 等 JSON 路径取值。批次未选入的普通明细仍可通过 `report-refs` 查询，未显示不等于未取得。

正文需要说明资料限制时，使用阅读材料或 `report-refs` 提供的有效覆盖、状态说明引用；`limitations[].id` 或不可用指标ID不能因为用于解释缺失就变成有效数值引用。找不到相应有效来源时不编造引用，保留已有固定数据说明。

| `identityStatus` | 字符串 | `verified` 精确核验通过；`unmatched` 未精确匹配；`unqueried` 未查询。核验通过只证明身份，不证明信用正常。 |

`actions[]` 的 `findingId/object/periods/count/amount/evidence` 分别指对应风险ID、事项、期间集合、发生条数、事项金额和证据；`materials/steps/completionCheck/text` 为需核对资料、办理步骤、完成核对标准及动作文字。`completionCheck` 是待执行的核验要求，不是已完成的处理结果；不得补造责任人、期限或完成状态。

## 17 个模块与限定降级语义

数据范围包括纳税人档案、应申报清册、增值税申报、企业所得税预缴及年度汇算、资产负债表、利润表、印花税、房产税、城镇土地使用税、缴款、欠税及退税、纳税信用、开具发票、取得发票、用途确认及抵扣、工商及公开信用信息。各类含义见[字段说明](fields.md)。

17 个模块仍先按统一任务补查两次。补查后只接受三类限定降级：`arrears_and_refunds` 的终态失败；`property_tax/urban_land_use_tax` 仅返回精确的空税源结果；税局已确认小规模纳税人时 `deduction_confirmations` 返回一般纳税人功能不适用。模型必须保留已成功返回的客观事实，成功空税源按未查到税源处理，独立保留已申报数据，小规模抵扣模块按不适用处理。其余失败、混合错误或运行中状态仍阻断报告。

核对资料时区分更新时间、记录数量和数据状态。客户文档使用中文业务名称及已确认的展示值，不直接粘贴原始 JSON 或字段路径。JSON `null`、缺失字段和空字符串保持缺失语义，不得作为数字零参与规则或图表。

## 动态章节

章节随适用范围和已取得资料显示，正文与目录的标题、编号应一致。

风险分布和重点事项仅在确认风险时生成。跨年窗口或必要金额/关联不足使用单条数据说明，不能称未见异常。财报全缺第八章一条数据说明，无空子节；行业品类全缺隐藏子节。无确认风险隐藏第十章，有风险仅列实际风险处理和跟踪；第十一章为3—5条重点。

发票统计张数取返回的 `count`，不能用统计组数量代替，也不自行新增去重。发票总体、趋势、品类、客户供应商排行、集中度和行业分析使用同一分析范围：只排除规则明确要求排除的作废或撤销状态，金额和税额保留原始正负号，不根据“红字”文字强制改号。品类明细与票面总额存在差额时，差额保留为“未识别/未分摊”；缺少品类只影响行业分析，不得改变发票总额。

`3.16` 对每个完整跨年窗口分别计算：分母为当年12月销项蓝字不含税金额，分子为次年1—3月与这些12月原蓝票明确关联的红字不含税金额绝对值。红字记录缺少原蓝票号码、金额缺失或12月蓝字金额为0时，不得用总红字金额代替对应红冲金额，也不得计算比例或风险等级。

工商及公开信用信息覆盖企业自身和主要交易对手。主体核验优先按税号，缺少税号时按完整企业名称精确匹配；模糊候选不得进入报告，同名不同税号不得混并。主要客户、供应商的核验数量采用与其交易排行一致的前五/前十规则。

企业自身身份无法核验、工商详情缺失或查询失败时，须保留缺失原因；查询成功但没有公开记录是另一种状态。对手方未精确匹配时，使用命令返回的 `warnings` 说明限制，不采用模糊结果。

股东及出资、主要人员、分支机构、变更记录和公开信用事件只展示已取得事实。分页未完整取得时，不把首屏作为全部记录。持股比例以百分数展示；明确以万元提供的处罚及违法所得金额，在报告中换算为元，执行金额维持元口径，不重复换算。决定内容未明确金额或单位时保留原文，不推测。

登记状态、公开信用记录和明确返回的直接股东/分支关系可用于主体分析；不得以名称、地址或电话相似新增关系。未提供的专利、商标、行政许可、限制高消费、整体诉讼和行业专项许可不得用其他字段推断。

## 税表阅读口径

- 5.1、5.2按当期应补退增值税与当期销售额展示税负，5.3使用同一应补退字段比较变化。本年累计销售额与完整性说明另行核对，不能混入当期认证金额。5.1主表包含所属期、申报销售额、销项发票金额、认证购进金额、认证购进税额、本期应补（退）增值税和税负率；累计缺期保持缺失。
- 5.1购进金额、税额取抵扣所属期认证清单中的金额和票面税额，不以开票日期或有效抵扣税额替代。应补退税额与应纳税额合计分别使用。5.5按财报实际所属期比较同期增值税本期销售额，月对月、季对季、年度单列；不对增值税本期值再差分，缺少任一月份不能视为完整季度。
- 增值税销售额的本期、累计、一般项目、即征即退项目以及不同业务类别分别核对。税额、减免、表内已缴、应补退和真实缴款含义不同，合计行不与子项重复相加。附表税率行中的“其中”子项不重复计入；小规模未开票额按申报销售额减销项不含税净额比较，红字保留原符号。
- 6.2收入和6.4利润还原单季时使用同年相邻前期参考，参考季度不得进入当前报告行。财报按截止日期排序，同日季度在年报之前，年报不能插入季度差分序列。增值税、企业所得税季报及财报的 `yearToDateReference` 只供累计或差分；参考期缺失或失败须说明。
- 民非报表“收入合计”按“本年累计数→合计”理解，非限定性、限定性与合计不得重复相加。当期与累计收入分别保留；资产负债表分别核对左右项目及年初、期末数。
- 6.6研发加计扣除比例的分母为同期间财报累计营业收入；年度与季度分别列示，年度金额和项目数量不得混用。6.7保留季度第29行、年度第32行“抵免所得税额”的独立含义。
- 附加税的“本期已缴（费）额”用于已缴栏核对。来源没有明确单位时，不推定税率或金额单位。
- 6.3展示财务成本及不重复计入研发费用的期间费用。工资数据不足时，扣除工资后的差额保持缺失；不以综合所得合计、社保缴费工资或年度 A105050 金额替代。
- A105000区分账载、税收、调增、调减四列；A107012第51行是年度加计扣除，不当成第四季度研究费用。年度与第四季度独立，财报“研究费用”作为管理费用其中项只计一次。
- 最近参考年度与本期所得税记录分开。营业账簿历史存在缺段时，不得称完整历史最高；买卖合同覆盖以发票净额估算，不能直接认定应补税。
- 房产税、土地使用税按当期已申报事实纳入，不因税源当前失效排除历史申报。土地税率单位为元/平方米，面积与计税依据不互代；保留原表分项舍入差异。
- 税种按征收项目区分，品目须属于对应项目；合并申报表各税费金额取各自中文行，不复制整表合计。明确金额、缺失、不适用、文本说明和查询失败不得互相替代，未知代码不自行解释。
- 4.1、7.6分别展示实际税费种认定和申报情况，缺少清册不能由申报清单反推漏报。预收账款、合同负债、固定资产和投资性房地产是独立财报项目，只作有依据的辅助核对。6.1使用申报应补退所得税额，具体规则见[报告规则](report-rules.md)。

## 逐节量化与来源记录

按[逐节分析约定](report-analysis.md)使用本批指标和分析目标：`text` 填写自然语言，`evidenceRefs` 独立保存来源 ID，提交时复制 `report-read` 返回的 `analysisDataDigest`。技术校验通过后渲染，不另设语义审读文件；底稿与引用不进入客户文档。

年度所属期的“本期金额”就是全年金额；只有本期值不可用时才读取同年度累计值，不能因表头不写“累计”就漏年度收入、成本、利润或现金流。本年累计优先读取明确累计列，否则仅汇总从年初起连续完整、同周期且不重叠的本期金额；同期间冲突停止累计。财报“上年年末余额”为年初基数，完整中文行名规范空白和全/半角括号后匹配；资本净变动不等于新增资本或应补印花税金额。

未申报事项应结合税局返回的申报期限、查询日期及明确状态判断。原始 `filingDeadline` 保留申报期限（`sbqx` 原值），`observedAt` 为查询日期，`sourceType/sourceStatus/filingState` 为来源类型、原始状态与申报状态。原始期限缺失时不自行补入法定日期，未明确含义的状态代码不得直接用于判级。

| 字段 | 类型 | 含义及使用方式 |
| --- | --- | --- |
| `id/taxName` | 字符串 | 事件标识及税费种名称。 |
| `period` | 对象 | 实际税款所属期 `TaxPeriod`。 |
| `kind` | 字符串 | `not_due` 未到申报期限；`overdue_unfiled` 逾期未申报；`late_filed` 已逾期申报；`corrected` 更正申报；`unknown` 资料不足以判断。更正不等于当前仍漏报。 |
| `deadline/filedAt/observedAt` | 日期字符串，可缺省 | 申报截止日期、实际申报日期、查询观察日期，三者不可互代。 |
| `overdueDays/hasOverdueDays` | 整数（可缺省）/布尔值 | 逾期天数及是否已知；`hasOverdueDays=false` 时天数未知，不能以默认0认定未逾期。 |
| `source/sourceStatus` | 字符串，后者可缺省 | 事件来源说明及原始状态；不同来源的状态码不可混用。 |


## 分批写作与成品复用

完整序列、表格和计算输入保存在底稿。默认阅读对财务、增值税概览、扣除凭证章节优先提供重点及其计算两端、合计、极值、负值和限制，普通逐期细节按需用 `report-refs` 读取；有已确认风险的章节保留相应事实材料。业务品名按方向展示绝对金额前十及重点、负数对象；供应商信用的采购品名按主体展示主要品名并保留重点、负数和缺失项。重点阅读及其金额覆盖率不等同于完整业务或履约核验。

工商详情与公开事件的查询状态分别说明。只有实际数量已知时才能报告记录条数，明确总数与已返回条数须区分；仅凭空集合不能认定查询成功且无记录，缺少查询结果或查询失败也不是零。金额比较应保留实际覆盖期间和比较对象；描述连续区间时区分净变化、观察点数及相邻比较次数。

`report-write` 接受 `analysisDataDigest`、`sections`、`conclusion`，正文使用 `text/evidenceRefs/objectiveIds` 结构。校验会检查提交字段、条目数和引用是否可用，Agent 仍须自行核对正文是否准确表达引用。工作区版本不匹配时重新 `report-prepare`，不手工修改摘要。

已生成的成品位置见 `render-result.json`，不要仅为查询路径重复渲染。修改正文后，须重新 `report-validate` 再 `report-render`；核对工作区与指定输出目录对应的两种成品。
