# 异常与任务状态处理

先区分HTTP/外层业务调用失败与`data.status`中的任务状态。`code=0`只说明这次调用成功，不代表17个模块已经全部完成。任务结构和错误码详见[接口契约](api.md)。

| 结果 | 下一步 |
| --- | --- |
| API Key、能力权限或企业归属不满足 | 停止，展示实际原因和对应绑定操作；不重试为“空数据”，不换企业 |
| 登录状态未就绪且快速登录不能继续 | 展示执行层返回的完整手动登录网页入口；用户完成后继续原命令 |
| 登录查询/预检超时或失败 | 说明无法确认状态，保留实际原因；不等同登录过期，不自动循环登录 |
| create非零，含3997 | 说明新任务未成功受理；保留原期间和可用traceId，不宣称已启动、不改短期间试建 |
| pending/running | 使用同一taskId继续query；不循环create |
| interrupted且retryable=true | 同一taskId继续query等待后台恢复；不提前交付、不新建任务绕过恢复上限 |
| interrupted不可恢复或缺少恢复信息 | 保留taskId、部分结果和原因并停止，不生成完整报告 |
| partial_success/failed | `report-prepare`复用原任务补查两次，不自动强刷；之后按数据契约的限定降级和阻断规则处理 |
| success且某集合为空 | 本次查询成功、无对应记录；需要金额或可比数据的分析仍按缺口处理，不把未知填零 |
| stale/refreshError | 说明当前数据仍为旧结果并带刷新错误；不能当本轮完整新数据 |
| report-validate失败 | 按missingPaths、invalidReferences、contentErrors及issues定位结构或引用字段错误；修正后重新校验，valid=true后直接渲染 |
| 任一格式渲染失败 | 不交付单边Word/PDF；保留实际错误，修复后重新成对生成 |

税务业务请求由CLI统一执行至少5秒间隔，同一环境/API Key跨进程共用；不足5秒时等待完整5秒，默认查询轮询间隔也是5秒。不要通过新进程、并行命令或缩小`--poll-interval`绕过；本地分析/校验不需要额外sleep。接口失败后的已允许重试同样受间隔限制。

只有用户明确要求全部刷新时才使用`--force-refresh`。限频不是无限重试授权；认证、权限、登录及参数错误仍按上表停止。
