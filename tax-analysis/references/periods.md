# 企业与分析期间

用户提供完整企业名称或USCC时，命令会查询当前API Key的绑定列表并精确核验。唯一匹配即使用该企业，不再要求用户从列表重复确认；沿用本会话已经明确选择的企业。未指定企业时执行`enterprises`并让用户选择；重名时需要USCC。不得模糊选择或自动绑定企业。

期间按中国日历换算，先用当前日期解析，再向用户说明明确的起止月份。用户已经给出的起止月份或完整日期优先，不能擅自缩短报告范围。只支持自然月边界；非整月日期先明确该请求是否可以按整月分析，不能静默扩大日期范围。

| 用户表达 | 起止月份 |
| --- | --- |
| 2025年/2025全年 | 2025-01至2025-12 |
| 去年 | 上一个自然年的01月至12月 |
| 今年/今年以来 | 当年01月至最近已结束的自然月 |
| 今年上半年/2025上半年 | 指定年份01月至06月；尚未到期时说明可取数范围，不能编造未来数据 |
| 2025年第一季度 | 2025-01至2025-03；第二/三/四季度同理 |
| 近N个月 | 以最近已结束的自然月为末月，向前数N个月，包含首尾 |
| 近12个月/最近一年 | 最近12个已结束的自然月 |
| 近三年 | 最近36个已结束的自然月 |
| 最近三个完整自然年 | 上一年12月结束，向前覆盖三个完整自然年 |
| 明确要求包含本月/截至本月 | 末月使用当前月；解释当月未结束，取数不完整不补零 |

例如当前日期为2026-09-08：“近12个月”为2025-09至2026-08，“近三年”为2023-09至2026-08，“今年”为2026-01至2026-08，“最近三个完整自然年”为2023-01至2025-12。该日期只是换算示例，不固定在实际任务中。

缺少年份且上下文无法确定的“上半年/第一季度”需补充年份。1月询问“今年”时尚无已结束月份，应说明情况，再按用户明确的当月或其他期间执行。

`startMonth/endMonth`使用`YYYY-MM`，首尾均包含、最多36个月、不能早于2017-01。超界时说明实际范围及限制，不自动截断。财报季度、税费所属期的月季计算由脚本处理，不改变用户选定的查询范围。
