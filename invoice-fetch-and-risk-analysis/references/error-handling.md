# 发票获取及风险分析错误处理

本文件定义预检、权限、取票轮询、附件下载、统计、风险报告和 PDF 生成的错误处理。通用接口异常文案匹配见 [common-handle-response-exception.md](./common-handle-response-exception.md)。

## 预检失败

- 预检失败时立即停止后续取票、附件、统计和风险分析流程。
- 必须读取预检命令生成的 Markdown 报告正文并原样展示。
- 不摘要、脱敏、重排、补充猜测或自行改写报告。
- 报告中的 `login_status=null` 或 `status_assessment=unknown` 只表示状态未知；仍必须按标题和 `cause_category` 明确说明是登录状态查询超时、快速登录前置/预检/执行/复查超时、其它请求失败、不满足快速登录条件或地区切换限制，不得只输出“状态未知”，也不得解释为登录失效。
- 登录检查失败报告提供安全登录地址时，必须原样完整展示，作为用户手动尝试登录的兜底入口；提供入口不改变上述原因判断，也不代表已确认登录失效。Agent 不得自行拼接地址。
- `auto_retry_allowed=false` 时不得自动重新执行预检。命中 `region_switch_rate_limited` 时必须停止自动重试和跨地区切换，等待用户稍后重新发起。
- 报告指向 workspace 不可用或需要重新指定目录时，用 `workspace-config-writer` 更新后重新预检。
- 只有重新执行预检并确认通过后，才能继续业务流程。

## API Key 与权限错误

- 预检报告、接口响应、stdout 或 stderr 出现“无权调用该能力”时，按 API Key 能力或企业绑定问题处理。
- 原样展示预检 Markdown 后，提示用户按 README 的 API Key 获取方式为当前 API Key 绑定发票批量获取能力及企业。
- 不引导用户去税局登录、重新登录或继续快速登录。
- 重新预检通过前不得继续 `fetch-invoices`、`fetch-attachments`、`fetch-deduction`、统计或风险分析。

## 接口响应异常

接口响应或 CLI 内部接口返回异常时：

1. 先检查是否命中业务场景定义的失败状态，例如任务状态 `data.status == -1`。
2. 再检查响应中是否存在异常 `message`。
3. 命中后按 [common-handle-response-exception.md](./common-handle-response-exception.md) 的 message 匹配表输出用户提示。
4. 匹配不到时展示原始 `message`。
5. 展示后立即终止当前流程。

当前文档不声明稳定的系统级 `code -> message` 映射；不要把可选示例错误码扩展成全局规则。

## 参数缺失或冲突

- 缺少显式 `uscc`、开始日期、结束日期、输出要求或是否下载发票原件/附件的确认结果时，不创建任务 JSON。`areaCode`、`personalAccount` 由脚本查询企业列表获得，不向用户追问。
- 日期无法解析或开始日期晚于结束日期时，一次性列出冲突项并要求用户确认。
- 用户要求风险分析但企业画像自动查询失败或字段不完整时，追问纳税人类型和行业或经营范围；未补齐前不进入风险分析。
- 用户明确只要获取或统计时，不强制追问纳税人类型和行业。

## 取票轮询失败或超时

- `fetch-invoices` 创建同步任务失败时，展示命令返回的错误或公共异常提示，并停止后续步骤。
- 已有 `execution.fetch_invoices.sync_task_id` 时，使用原任务再次执行 `fetch-invoices --task-file <task.json>` 续查，不创建新的同步任务。
- 轮询中 `data.status == 1` 表示成功。
- 轮询中 `data.status == -1` 表示失败，必须停止当前及后续流程。
- 其他状态继续按执行层退避策略轮询；30 分钟仍未完成时报告超时，不得另建新任务伪装重试成功。

## 附件下载失败

- `fetch-attachments` 创建或轮询失败时，停止附件分支，并说明发票获取和摘要是否已完成。
- 附件远程链接下载部分失败时，保留已成功下载的本地文件，记录总数、成功数、失败数和失败原因。
- 附件部分失败不自动阻断统计；若用户要求风险分析且附件缺失会影响结论，必须在风险边界说明中标注。
- 不直接把远程签名 URL 当成最终结果展示。

## 勾选已认证数据失败

- 企业画像不是 `一般纳税人` 时，仍必须让 `fetch-deduction` 写入 `execution.fetch_deduction.status=skipped` 和跳过原因，再继续生成发票清单；Agent 不得只凭画像自行跳过命令。
- 一般纳税人执行 `fetch-deduction` 失败时，说明失败影响范围并停止清单、统计和风险分析；不得生成“勾选状态未确认”的报告代替该步骤。
- 勾选任务轮询 `data.status == -1` 或 30 分钟超时时，按失败处理，不再新建任务。

## 统计分析失败

- `analyze-invoice-data` 执行失败时，不得输出伪造统计结果。
- 已完成取票、附件或清单的，应明确列出已完成产物和统计失败影响范围。
- Excel 生成失败、`outputs.analysis_excel_path` 缺失、文件不存在或无法打开时，统计分析按失败处理。
- 只有脚本在失败分支明确保留了统计临时 Markdown 兜底内容时，才允许展示该兜底正文或路径；成功路径不得展示临时 Markdown。
- 统计 workbook 未确认存在并完成用户可见路径输出前，不得进入统计摘要或风险分析。

## 风险分析与数据转换失败

- `build-invoice-context-data` 因勾选未执行、勾选文件缺失、清单未在勾选后重生成或清单已过期而失败时，按错误提示依次补跑 `fetch-deduction`、`generate-invoice-list`，再重试构建；不得绕过门禁，也不得直接把原因写成“当前数据不包含勾选状态”。
- `build-invoice-context-data` 返回其他失败时，立即停止风险分析。
- 返回 `partial_success` 时可以继续，但风险报告必须包含受影响文件和影响范围。
- 分析版数据不可读、缺少源文件映射或无法追溯关键结论时，停止风险分析并提示补齐后重跑。
- 风险报告生成后发现必备章节缺失、包含表情符号或与提示词结构不一致时，必须在进入 PDF 前补全或重生成。

## 报告和 PDF 生成失败

- 风险 Markdown 保存失败时，不得进入 PDF 转换，也不得声称风险分析完成。
- 报告中出现未翻译的脚本内部英文标识属于内容质量问题，不属于 PDF 转换失败。Agent 必须结合英文内容的来源和语义，将内部标识翻译为用户看得懂的中文，改写同一份报告、覆盖原 Markdown，并重新调用 `markdown-to-pdf`；不得使用英文字母正则或固定词表一刀切，不得只交付 Markdown，也不得声称任务完成。
- `markdown-to-pdf` 报告 NotoSansSC 字体缺失、不可用或无法加载时，先停止转换并保留 Markdown；按远端安装文档的“PDF 字体下载表”重新下载两份字体到 `assets/fonts/` 原始文件名，确认非空后再重试，不得猜测字体 URL 或改用系统字体。
- 只有字体、文件读取、渲染或写入等真正的 PDF 技术故障在按对应规则重试后仍失败，才交付已生成的 Markdown 正文和路径，说明 PDF 未生成及失败原因；不得调用 `finalize-risk-artifacts`，不得删除 Markdown、勾选已认证 JSON、压缩风险上下文或发票清单分析版上下文 JSON。
- PDF 生成成功后，带 `--task-file` 的 `markdown-to-pdf` 必须已在脚本内清理中间 Markdown、勾选已认证 JSON、压缩风险上下文和上下文 JSON；若脚本内清理失败，按结果不完整处理并说明清理失败影响范围。
- 对话中展示的风险报告正文必须与已保存 Markdown 一致；如果无法确认一致性，停止并重新读取 Markdown 后再展示。

## stdout 成功但结果不完整

- stdout 显示命令成功，但任务 JSON、`发票统计分析.xlsx`、风险 PDF 文件或本地产物目录缺失时，按结果不完整处理。
- 风险 PDF 成功路径还必须确认 Markdown、勾选已认证 JSON、压缩风险上下文和发票清单分析版上下文 JSON 已由 `markdown-to-pdf --task-file` 清理；PDF 失败路径必须确认 Markdown 兜底仍保留。
- 不能用 stdout 摘要替代应展示的报告正文。
- 不能只展示文件路径替代摘要或风险报告正文；统计分析成功路径必须展示 workbook 路径，可选摘要不能替代 workbook。

## 编码和命令错误

- Windows 中文 JSON 输入优先使用 UTF-8 文件和 `--input`。
- `Unexpected UTF-8 BOM` 按编码兼容问题处理，重写为 UTF-8 无 BOM 或使用兼容读取。
- JSON parse error 先检查文件编码、转义、根对象和字段名。
- DNS、TLS、代理或网络错误不应转化成业务字段错误；报告网络或环境问题并停止当前自动推进。
- 登录状态查询、快速登录预检或快速登录请求发生网络错误时，只能说明当前无法确认登录状态；必须同时展示报告提供的手动登录兜底链接，但不得据此追加税局登录失效结论或自动重试。
