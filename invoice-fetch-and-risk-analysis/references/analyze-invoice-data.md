# 场景：analyze-invoice-data（发票数据分析）

## 模板用途

用于对指定发票 Excel 文件或目录进行汇总分析，输出六大维度统计结果，支撑后续风险分析与经营判断。

## 触发关键词

发票数据分析,发票统计分析,发票汇总分析,分析发票清单,发票六维统计,进销项统计,客户供应商集中度,月度发票分析

## 场景说明

- 业务目标：汇总多个发票文件中的“发票基础信息”数据，并完成六个维度的统计分析。
- 典型用户：会计、财务负责人、税务顾问、AI Agent 编排流程。
- 使用前提：提供本地单个 xlsx 文件路径，或提供包含多个 xlsx 文件的目录路径。
- 输入来源：用户输入参数 + 文件系统扫描结果。

## 输入与约束

| 输入项          | 是否必需 | 说明                         | 缺失处理                                |
| --------------- | -------- | ---------------------------- | --------------------------------------- |
| input_file_path | 否       | 单个待分析 xlsx 文件路径     | 与 input_dir 二选一，均缺失则报错       |
| input_dir       | 否       | 待批量分析目录（非递归扫描） | 与 input_file_path 二选一，均缺失则报错 |
| task_file       | 否       | 任务 JSON 文件路径           | 传入后优先从任务 JSON 读取分析输入路径  |

说明：

- 支持单文件和目录批量分析。
- 分析目标 sheet 固定为“发票基础信息”。
- 当传入 task_file 时，脚本需从任务 JSON 的 `intent.params` 或 `artifacts` 读取输入路径，生成 `发票统计分析.xlsx`，并将路径写回 `outputs.analysis_excel_path`。脚本执行中可使用临时 Markdown 组织统计内容，但成功返回前必须删除该临时文件，且不得写成最终用户路径。

## 执行逻辑

1. 解析输入参数并校验来源：

- 若提供 input_file_path，则分析单文件。
- 若提供 input_dir，则扫描目录下所有 .xlsx 文件并逐个加载。

2. 加载发票数据：

- 读取每个文件的“发票基础信息”sheet。
- 将所有文件数据汇总为统一数据集。

3. 自动标记发票方向：

- 文件名包含“开具发票” -> 该文件全部行标记为“销项”。
- 文件名包含“取得发票” -> 该文件全部行标记为“进项”。
- 均不包含时，视为无法识别进销项，并在 warnings 中提示。
- 只要存在无法识别方向的文件，本次结果不进行方向统计。

4. 附件总数统计：

- 优先统计“本地发票附件地址”列中非空值数量（去重）。
- 若该列不存在，则按输入规则尝试查找“发票附件”目录并统计 .pdf 数量：
  - 输入为文件路径：去文件上级目录查找。
  - 输入为目录路径：去输入目录同级目录查找。

5. 执行六维统计分析：

- 总体统计
- 方向统计
- 类型统计
- 状态统计
- 时间统计（月度、季度、年度）
- 对象统计（前五客户、前五供应商、集中度）

6. 输出分析结果：

- 生成 `发票统计分析.xlsx`，写回任务 JSON 的 `outputs.analysis_excel_path`；workbook 仅包含一个名为“发票统计分析”的 sheet。
- 当本次任务为“获取+统计”且不进入风险分析时，脚本成功后删除发票数据摘要 Markdown、勾选已认证 JSON 和统计临时 Markdown，并清理 `summary_markdown_path`、`deduction_data_file`、`analysis_markdown_path` 等中间引用；当本次任务为“获取+分析”时，摘要和勾选数据保留到风险 PDF 成功后由 `markdown-to-pdf --task-file` 统一清理。
- 单个“发票统计分析”sheet 必须按总体、方向、类型、状态、时间、客户/供应商的顺序覆盖六类完整统计表，各一级统计区块之间保留一个空行。
- workbook 不得写入“统计摘要”文字区、摘要正文或摘要说明；可选统计摘要只能在对话中单独输出。
- 成功路径只向用户展示 `outputs.analysis_excel_path` 指向的 workbook 路径，并可额外输出“统计摘要汇总”，按 `1、总体概况`、`2、发票类型与状态`、`3、时间分布特征`、`4、客户与供应商结构` 四段组织。
- 统计摘要汇总应以脚本产出的统计结果为基础，由 Agent 按 [发票数据统计分析提示词](发票数据统计分析提示词.md) 进行查漏补缺、口径补齐和适度美化后输出。
- 统计摘要汇总需对齐 [发票数据统计分析提示词](发票数据统计分析提示词.md) 的文本摘要要求与数据口径说明，突出总体规模、结构特征与时间趋势，长度控制在 500 字以内。
- 输出要求结构清晰、详细、语义化。
- 不支持或无法计算的维度不展示。

## 编排规则（强制）

当 Agent 在“发票获取及风险分析”主场景中执行统计分析步骤时，必须严格按以下顺序完成，不得跳步，不得仅输出最终结论：

1. 先确认统计分析输入来源：

- 优先使用本次触发流程内“获取发票”步骤产出的原始发票 Excel 文件或其所在目录。
- 不得改用“生成发票清单”或其他后处理产物作为统计主输入。

2. 再确认执行方式：

- 若当前为编排流程内执行，必须优先使用 `--task-file`。
- 从任务 JSON 中读取分析输入路径、附件目录及上下文信息。

3. 检查附件统计口径：

- 若同批次已执行“获取发票附件”，则可结合同批次本地“发票附件”目录补充附件数量统计。
- 若未执行附件步骤，则仅基于原始 Excel 或其附带字段统计。

4. 执行统计分析脚本：

- 调用 `analyze-invoice-data`。
- 确保 `发票统计分析.xlsx` 写回任务 JSON 的 `outputs.analysis_excel_path`，成功时不存在最终临时 Markdown 路径。

5. 输出前检查交付物：

- 必须检查 `outputs.analysis_excel_path` 指向的本地 workbook 存在、可打开，且文件名为 `发票统计分析.xlsx`。
- 必须确认 workbook 只有一个名为“发票统计分析”的 sheet，并已按顺序覆盖总体、方向、类型、状态、时间、客户/供应商六类统计表。
- 必须确认 workbook 内不存在“统计摘要”文字区或摘要正文。

6. 对话回显：

- 必须将 `outputs.analysis_excel_path` 对应的 workbook 路径作为统计最终交付物发送到用户可见的对话框内。
- 不得展示内部任务 JSON、临时 Markdown 路径或脚本内部中间内容。
- 可在路径后输出简短统计摘要，但摘要不得替代 workbook。

7. 生成统计摘要汇总：

- 只有在 `outputs.analysis_excel_path` 已确认并发送到对话框后，才可生成“统计摘要汇总”。
- 统计摘要汇总必须以脚本产出的统计结果为基础，由 Agent 按 [发票数据统计分析提示词](发票数据统计分析提示词.md) 进行查漏补缺、口径补齐和适度美化。
- 统计摘要汇总必须对齐 [发票数据统计分析提示词](发票数据统计分析提示词.md) 的文本摘要要求与数据口径说明，突出总体规模、结构特征与时间趋势，且长度控制在 500 字以内。
- 统计摘要汇总必须作为 workbook 路径之后的单独对话输出，不得写入 workbook，也不得替代 `outputs.analysis_excel_path`。

8. 后续流程控制：

- 在 `outputs.analysis_excel_path` 完成检查和用户可见输出、且可选统计摘要汇总完成输出之前，不得进入风险分析或其他后续步骤。
- 若统计结果可复用，也必须先完成上述回显与摘要输出，再决定是否继续后续流程。

## 六维统计口径

1. 总体统计

- 发票总张数
- 附件总数
- 总金额
- 总税额
- 价税合计

2. 方向统计

- 进项发票张数 / 金额 / 税额
- 销项发票张数 / 金额 / 税额

说明：若输入文件名不包含“开具发票”或“取得发票”，导致方向无法识别，则该维度统计整体跳过，并在结果中返回跳过原因。

3. 类型统计

- 专票数量 / 金额
- 普票数量 / 金额
- 电子票数量 / 金额（如适用）

4. 状态统计

- 正常发票数量
- 红冲发票数量
- 作废发票数量

5. 时间统计

- 月度发票数量变化
- 月度金额变化
- 季度对比
- 年度对比

6. 对象统计

- 前五大客户
- 前五大供应商
- 客户集中度
- 供应商集中度

## 执行规则（建议）

1. 仅处理 .xlsx 文件，忽略临时文件（如 ~$ 开头）和其他扩展名文件。
2. 任一文件失败不应中断整个批次，失败文件进入 errors。
3. 数值字段无法解析时按 0 处理，并记录 warning。
4. 日期字段无法解析时不参与时间统计，并记录 warning。
5. 所有统计结果保留两位小数。
6. 若文件名无法识别进销项方向，不进行方向统计，并在 warnings 中返回受影响文件。

## 输出规则（强制）

1. 当以 `task_file` 方式执行时，`发票统计分析.xlsx` 必须写回任务 JSON 的 `outputs.analysis_excel_path`。
2. workbook 必须只有一个名为“发票统计分析”的 sheet，并按顺序完整覆盖总体、方向、类型、状态、时间、客户/供应商六类统计表；各一级统计区块之间保留一个空行。
3. 成功路径不得把脚本内部临时 Markdown 作为最终文件路径、对话正文或用户可打开产物展示。
4. Agent 必须检查 `outputs.analysis_excel_path` 对应文件存在，再将该路径发送到用户可见的对话消息中。
5. 仅说明“已生成统计结果”不算完成用户可见输出；必须给出可打开 workbook 路径。
6. 在 workbook 路径完成用户可见输出之前，不得继续执行后续流程，尤其不得直接进入风险分析。
7. Agent 可再单独生成并输出“统计摘要汇总”。
8. 统计摘要汇总必须以脚本产出的统计结果为基础，由 Agent 按 [发票数据统计分析提示词](发票数据统计分析提示词.md) 进行查漏补缺、口径补齐和适度美化后输出。
9. 统计摘要汇总必须对齐 [发票数据统计分析提示词](发票数据统计分析提示词.md) 的文本摘要要求与数据口径说明，突出总体规模、结构特征与时间趋势，且长度控制在 500 字以内。
10. 统计摘要汇总不得写入或替代 `发票统计分析.xlsx`。

## 交付要求

### 用户可见结果

- 输出内容：六维统计结果。
- 输出形式：`发票统计分析.xlsx` 文件路径 + 可选对话内简短统计摘要。
- 可追溯性：可定位到 source_files、failed_files、warnings。
- 当以 task_file 方式执行时，必须先确认 `outputs.analysis_excel_path` 指向的 workbook 存在并完成用户可见输出；随后可单独输出统计摘要汇总。

## 质量标准

- 完整性：输出六维统计结果。
- Excel 完整性：单个“发票统计分析”sheet 覆盖六类完整统计表，不包含“统计摘要”文字区，且不得退化为摘要版。
- 准确性：方向标记和统计口径符合规则。
- 可解释性：统计结果可读且可追溯。
- 可行动性：输出结果可直接用于后续风险分析。
- 维度展示：不支持或无法计算的维度不展示。
