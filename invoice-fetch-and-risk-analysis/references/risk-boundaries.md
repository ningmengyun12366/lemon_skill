# 发票获取及风险分析风险边界

本文件定义发票获取、附件下载、统计和风险分析的安全边界。命中边界时停止自动推进，并按 [error-handling.md](error-handling.md) 输出。

## 正常路线边界

- 正常路线必须是：安装/README 门禁 -> CLI 可用性检测 -> `task-preflight-check` -> 参数确认 -> `init-task` -> `fetch-invoices` -> 按需附件、统计、风险分析。
- 不绕过 `task-preflight-check`、任务 JSON、用户可见输出门禁、企业画像补齐、发票清单生成或风险报告落盘。
- 新触发必须重新取票；不能把历史 Excel、历史附件目录、历史统计结果或历史风险报告当成本次输入。
- 业务操作通过文档中的 CLI 命令执行，不自行构造 HTTP 请求绕过预检或确认。

## 敏感信息边界

- 不要求用户在公开对话中暴露 API Key、token、cookie、税局密码、短信验证码、二维码、人脸材料或签名 URL。
- 不把 API Key、token、cookie、签名 URL、本机绝对路径写入参考文档、任务证据、runtime-config 或发布包。
- 不向用户展示内部任务 JSON 路径、临时目录、完整 payload、调试字段或远程签名下载链接，除非用户明确要求排查且内容已脱敏。
- 附件和 Excel 远程链接必须先下载或转成本地交付物，再向用户展示本地目录或本地文件结果。

## API Key 与能力边界

- “无权调用该能力”表示当前 API Key 未绑定 `invoice_batch_get` 能力或对应企业；不能解释成税局登录失败。
- 命中无权限后必须停止当前业务流程，按 README 的 API Key 能力绑定方式提示用户处理，并在重新预检通过前不得继续取票或分析。
- `40001 请求校验失败` 不能直接等同为 API Key 未绑定；应先检查 CLI、配置、企业字段、workspace 和任务输入结构。

## 发票数据与历史复用边界

- 每次用户消息触发新的取票或风险分析请求时，都按新任务处理并重新执行 `fetch-invoices`。
- 同一次任务流程内，已成功写入当前任务 JSON 的上游产物可被下游复用。
- 统计结果只能作为风险分析补充材料，不得替代发票清单分析版结构化数据。
- 风险分析主依据必须是当前任务的压缩风险上下文、发票清单全量数据、发票清单分析版结构化数据、企业画像和提示词约束；报告撰写优先使用压缩风险上下文，全量数据只用于追溯和复核。

## 风险分析边界

- 风险分析只能输出风险、疑点、边界和复核建议，不得武断定性违法。
- 不得只凭“进项大于销项”判定高风险；必须结合纳税人类型、行业、票种、状态、时间、对象集中度和原始明细。
- 一般纳税人与小规模纳税人的判断口径必须区分；小规模纳税人不得套用一般纳税人抵扣口径。
- 若 `build-invoice-context-data` 返回 `partial_success`，必须在报告边界说明中写明受影响文件、缺失范围和结论影响。
- 若结构化数据缺失、不可读或无法追溯到源文件，停止风险分析并要求补齐后重跑。
- 风险报告正文禁止 emoji、颜文字、装饰性图标或其它表情符号。
- 风险报告正文禁止原样展示脚本内部英文标识、字段名、枚举值、状态值、布尔值或调试文字；必须按业务含义翻译为用户看得懂的中文。不得把所有英文一律判错：源发票中的企业法定名称、商品型号、正式代码或通行缩写可以保留，但首次出现时必须紧跟中文说明。

## 报告一致性边界

- 摘要和风险 Markdown 必须先落盘或写回任务 JSON，再从同一来源原样展示；统计分析成功路径以 `发票统计分析.xlsx` 为最终交付物。
- 已保存的风险 Markdown、对话回显正文和 PDF 转换输入必须是同一份正文。
- 不得保存一版 Markdown、对话展示另一版、PDF 转换第三版。
- 中文可读性由 Agent 结合英文内容的来源和语义判断，不得使用英文字母正则或固定词表一刀切。发现未翻译的内部英文标识时，必须改写同一份报告并重新生成 PDF；这不是 PDF 技术失败，禁止只交付 Markdown。
- PDF 生成成功时，最终只告知风险 PDF 路径并展示报告正文；风险 Markdown、发票数据摘要 Markdown、勾选已认证 JSON、压缩风险上下文和发票清单分析版上下文 JSON 是中间产物，必须由带 `--task-file` 的 `markdown-to-pdf` 在脚本内自动清理。
- PDF 转换失败时，不运行 finalizer，保留并告知风险 Markdown 兜底路径和报告正文，同时说明 PDF 未生成原因。

## 附件与远程下载边界

- 不把远程签名 URL 作为最终交付结果。
- 不把远程文件打包进 ZIP；远程下载模型保持不变。
- 附件下载失败时保留成功文件并报告失败影响范围，不得把部分成功说成全部成功。

## 停止条件

以下情况必须停止当前自动推进：

- 安装文档或 README 门禁未完成。
- CLI 不可执行。
- `task-preflight-check` 未通过。
- 出现“无权调用该能力”。
- 必填字段缺失或字段冲突未确认。
- 日期范围超过 2 年且用户未二次确认。
- `fetch-invoices` 失败或 30 分钟内未终态。
- `fetch-deduction` 失败且本次风险分析依赖抵扣数据。
- `build-invoice-context-data` 失败。
- 风险分析缺少企业画像且自动查询与用户补充都未完成。
- 报告或 PDF 生成失败且无法确认用户可见交付物。
