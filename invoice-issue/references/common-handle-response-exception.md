# 场景：handle-response-exception（处理接口响应异常）

## 模板用途

用于统一处理接口直接响应异常，或本地 Go 二进制命令执行过程中调用接口后返回的异常响应。

## 触发关键词

接口响应异常、response 异常、脚本调用接口报错、接口返回 message。

## 异常定义

- 当响应对象中出现 `data.status = -1` 字段时，通常视为异常情况。
- 该规则同时适用于：
  - 直接发起 HTTP 请求后的响应。
  - 执行本地 Go 二进制命令时，命令内部调用接口后返回的响应。

## 执行逻辑

1. 先检查当前响应对象中是否存在 `data.code !== 200` 且 `message` 字段不为空的情况。

2. 若不满足以上条件，按原业务场景继续处理。

3. 若满足以上条件，立即判定为异常响应。

4. 发生异常响应后，根据以下规则，匹配到展示给用户的提示；如果匹配失败则直接展示 `message` 字段内容。

5. Agent 给出提示后，必须立即终止后续流程。

6. 当前阶段不做其它处理，包括但不限于：
   - 不补充解释
   - 不改写 message 文案
   - 不包装为新的模板
   - 不追加重试建议

- 不自行尝试修复问题
- 不继续后续业务步骤

## 输出规则

- 输出内容优先使用匹配后给用户的提示，匹配不到时，再展示`message`字段内容。
- 必须原样展示，不得翻译、摘要、改写、裁剪或增加前后缀。
- 展示完成后必须立即结束当前流程，不得进入自动修复、自动重试或补救分支。
- 若命中本场景，优先执行本规则，覆盖业务场景中的常规成功/失败模板。

## 示例

### 输入示例

```json
{
    "code": 9001,
    "data": null,
    "message": "当前公司有正在执行的任务",

}
```

### 输出示例

```text
用户登录已过期
```
